## 提示词链路映射修复（阶段 1 后）

用户反馈两个真实工作流（H3_文生图 / H3_修图，节点 32 为 `MiniMaxH3ImageConditioning`）导入后：无提示词输入框；或提交时提示词仍是 JSON 原值。
根因：`positiveField` 只认 CLIPTextEncode/TextEncodeQwenImage21 的字段，不认 ImageConditioning；且用户提示词藏在 `43.value -> StringReplace.replace(find="{input text}") -> TextGenerateV2.prompt -> JsonExtractString -> ComfySwitchNode -> PreviewAny -> 32.prompt` 链路里，`sourceField` 无法穿透，导致 `profile.prompt` 为空；映射下拉默认"保留工作流原值"，用户手动选则可能选中 36(system_prompt)/39(模板)，写入不生效。
修复：`src/library/mapping.js` 新增 `chainNodes` + `promptSource`（优先 `_meta.title` 含 user_prompt 的 primitive，其次带占位符的 StringReplace.replace，再其次 switch 分支），`positiveField` 支持 ImageConditioning 的 prompt；`mappingVersion` 升到 3，`repairSavedMapping` 仅在 prompt 为空时补入，尊重手动绑定。
测试：新增 `tests/test_h3_prompt_chain.py` 与两份真实样本 `tests/fixtures/h3-image-text.api.json`、`h3-image-edit.api.json`，断言自动选中 `["43","value"]`、提交后 43.value 为用户输入且 36/39 不变；全量 22 场景通过。
验证：直接对 `~/FrameformData/workspace.sqlite` 里的旧条目跑 `repairSavedMapping`，H3_文生图、H3_修图 均补为 `["43","value"]`，qwen 既有绑定不变；用户刷新页面即自动写回，无需重新导入。
备注：带素材槽位的工作流按既有设计不预填默认提示词（避免 `<Picture 1>` 与槽位冲突），输入内容现在会正确写入。
