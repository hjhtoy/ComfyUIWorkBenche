## 队列常驻“无法访问 ComfyUI 服务器”的原因与修复（2026-11-25）
- 现象：批量任务正常跑，但队列顶部一直显示“无法访问 ComfyUI 服务器…Cannot connect to host 127.0.0.1:7860”。
- 原因：13 小时前有 30 条批量任务指向已失效的本地隧道地址 `http://127.0.0.1:7860`（sent=True，状态仍 queued/running），Worker 每 5 秒重试一次并持续写全局 `connection` 提示；与当前 onethingAI 服务器无关。
- 修复：worker 新增 `self.unreachable`（base → 首次不可达时间）与 `CONN_GIVE_UP=600`；同一地址不可达超过 10 分钟即把该任务标记 `lost`，note=“无法连接服务器 <base>，已停止跟踪；请确认地址后重新提交”，不再永久重试。成功连上任一任务会清空该 base 的计时与全局提示。
- 同时把 `/prompt` 400 的错误体改为可读单行：`readable_error()` 提取 `error.message` + 前 3 个 node_errors 的 details，避免任务卡片显示截断的 JSON。
- 一次性数据修复：把 30 条 7860 僵尸任务直接标记 lost。测试：`test_worker_recovery.py` 增加 400 校验错误可读性 + 死地址收敛断言；全量 24/24。

## 队列显示当前节点与步数进度（2026-11-25）
- ComfyUI 的进度只走 `/ws`：`executing`（当前节点）与 `progress`（value/max）。事件按 `extra_data.client_id` 定向发送，所以订阅方必须用提交时的 clientId 连 `/ws?clientId=<cid>`。
- 后端：`workspace/worker.py` 对 running 的 comfyui 任务开一个 ws（`self.watchers`，每服务器仅运行中的任务），`note_progress()` 解析事件、`node_label()` 从 plan graph 取 `_meta.title`/`class_type`，存内存 `self.progress[cid]`；任务终态/超时自动清理。新接口 `GET /workspace/progress` 返回 `{clients:{cid:{label,value,max,at}}}`。
- 前端：`workspace-runner.js` 每秒拉一次进度，写入 `job.stage/value/total` 并局部 render；`queue-view.js` 新增 `.job-stage`（`标签 · N / M 步`），终态清空；进度条只在“有 total 或正在运行”时显示，排队任务不再显示半满进度条（原来无 value 的 `<progress>` 会被误读为 50%）。
- RunningHub 开放 API 没有节点级进度，保持排队/执行状态。
- 测试：新增 `tests/test_queue_progress.py`（mock `/ws` 推送 executing+progress，断言 UI 显示 2 / 6 步、接口快照、完成后清空）。全量 25/25。
- 实测 onethingAI 实例：`自定义采样器（高级） · 5 / 6 步` 正常。

## 修复：单文件 TXT 同名素材报错 + 批量目录选择（2026-11-25 下午）
- 单文件导入报“存在同名素材”：素材库常有同名不同内容的多份（pika-h3 库 29 组重名）。`composer.importStoryboard()` 现在按名字分组，优先用草稿里已引用的那份，否则取最近导入的一份，并在成功提示里说明“同名素材取了最近导入的一份：… 等 N 个”。批量导入仍走严格校验（目录里同名即报错，因为无法判定）。
- 批量导入报“未找到 prompts 下的 TXT”：`readBatchProject` 原来只认 `<所选目录>/prompts/x.txt`（深度 1）。现在任意深度查找 prompts：只找到一个项目就用它；多个则报“所选目录中有多个项目（…），请选择其中一个项目根目录”；若选中的就是 prompts 本身，提示“请选择上一级项目根目录（同级要有 assets）”。assets 路径按 root 前缀匹配，root 只取最后一段用于显示与素材文件夹命名。
- 测试：`test_txt_import.py` 增加重名场景；`test_project_batch.py` 增加“选父目录成功 / 多项目报错 / 选中 prompts 报错”。全量 26/26。
- 真实验证：`我的叔叔于勒/prompts/S24_应该把孩子们领开_11s.txt` 导入成功（3 素材，含重名说明）；目录 `/项目` 报多个项目、`…/prompts` 报上一级、`…/我的叔叔于勒` 68 条可提交。

## 重名素材改为“保留最新、移除旧条目”（2026-11-25 下午）
- 需求：重名时取最近导入的一份，并覆盖素材库里原来的条目。
- 实现：`composer.importStoryboard()` 在解析前调用 `pruneDuplicateMaterials()`：按文件名（NFC）从后往前遍历 `assets`，每个名字保留最后一个（最新），其余从内存数组和素材库记录（`frameform.material-library.v1.<pageKey>`）里删除；blob 保留在 IndexedDB/工作区，所以引用旧 id 的旧草稿仍能恢复。
- `rememberMaterial` 保持原样（允许同名不同内容共存），因此清理只发生在导入分镜时，不影响手动/批量上传同名素材的能力（`test_generation` 依赖这一点）。
- 提示文案：`素材库里的 N 条重名旧条目已移除，保留最近导入的一份。`
- 测试：`test_txt_import.py` 覆盖“上传同名 → 面板 2 份 → 导入后提示移除 1 条 → 面板 1 份”。全量 26/26。
- 真实数据副本验证：pika-h3 库 114 项（A03 有 3 份）→ 导入 S24 后 86 项、A03 剩 1 份、提示“28 条重名旧条目已移除”。
